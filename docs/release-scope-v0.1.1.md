# Theuth v0.1.1 — Release scope

This documentation update builds on the initial Theuth v0.1.0 framework while retaining its provider-neutral, portable, and adaptable approach.

## Included since v0.1.0

- AI-assisted getting-started guidance for applying Theuth without requiring new tooling.
- Guidance for stable internal identifiers and correspondence registries for externally named, unchanged original documents; optional hashes distinguish byte-level versions.
- An explicit principle distinguishing **verified provenance**, **fitness for contextual application**, and **verified outcomes**.
- A risk-proportionate contextual application extension to the retrieval workflow, with clear uncertainty and human review for consequential actions.
- Guidance to preserve the evidence, tested conditions, and known limits associated with reusable knowledge artifacts.
- A bilingual proposal and evaluation scenario in [contextual-application-proposal.md](../methodology/contextual-application-proposal.md).
- Related-work coverage of Greg Isenberg's commercially oriented agent-assisted manufacturing workflow, without adopting its domain-specific architecture.

## Maturity and limits

The contextual application extension is **proposed and documented, not experimentally validated**. It is guidance for future evaluation rather than proof that Theuth improves decision quality. Ordinary factual retrieval need not undergo needless external testing. This release does not mandate new folders, record types, agents, databases, or automated gates. TheuthMT and TheuthMTC remain flexible usage profiles.

The original [v0.1.0 release scope](release-scope.md) and [release notes](release-notes-v0.1.0.md) remain historical records; this document describes subsequent changes.

# Theuth v0.1.1 — Alcance de la versión

Esta actualización documental amplía el framework inicial Theuth v0.1.0, manteniendo su enfoque portable, adaptable e independiente del proveedor.

## Incluido desde v0.1.0

- Guía de inicio asistido por IA para aplicar Theuth sin requerir nuevas herramientas.
- Orientación para identificadores internos estables y registros de correspondencia de documentos originales cuyo nombre externo no debe alterarse; hashes opcionales distinguen versiones a nivel de bytes.
- Principio explícito que distingue **procedencia verificada**, **idoneidad para la aplicación contextual** y **resultados comprobados**.
- Ampliación del flujo de recuperación para aplicación contextual y verificación proporcional al riesgo, incertidumbre explícita y revisión humana ante acciones relevantes.
- Orientaciones para conservar evidencia, condiciones probadas y límites conocidos de artefactos reutilizables.
- Propuesta bilingüe y escenario de evaluación en [contextual-application-proposal.md](../methodology/contextual-application-proposal.md).
- Inclusión del enfoque comercial de fabricación con agentes de Greg Isenberg en trabajos relacionados, sin adoptar su arquitectura específica.

## Madurez y límites

La ampliación para aplicación contextual está **propuesta y documentada, pero no validada experimentalmente**. Se plantea para evaluaciones futuras; no demuestra que Theuth mejore la calidad de las decisiones. Una consulta factual ordinaria no requiere ensayos externos innecesarios. Esta versión no impone carpetas, tipos de registros, agentes, bases de datos ni barreras automáticas nuevas. TheuthMT y TheuthMTC siguen siendo perfiles flexibles.

Se conservan [el alcance de v0.1.0](release-scope.md) y [sus notas](release-notes-v0.1.0.md) como registros históricos; este documento describe los cambios posteriores.

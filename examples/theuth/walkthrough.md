# Walkthrough: from a conversation to a traceable answer

This walkthrough shows an example query about Theuth and the records that support an answer. It is a manual demonstration of the method, not an automated search.

## Query

**Which methodological approach was agreed for Theuth, and where did it come from?**

## Retrieval

1. Open the [current project file](project.md) to get oriented.
2. Follow the link to the [methodological decision](decisions/2026-09-23-methodological-foundation.md).
3. Consult the [attributed claim](claims/2026-09-23-hybrid-approach.md).
4. Open the [source record](sources/2026-09-23-methodological-design-discussion.md) and review its locator and limitations.

The [initial design snapshot](snapshots/2026-09-29-initial-design.md) is an optional historical checkpoint. Consult it when asking what state was preserved at the end of that milestone, not as a replacement for the current state.

## Answer

A hybrid approach was agreed, combining explicit provenance, compact snapshots, atomic decisions, progressive retrieval, and Git. The claim is attributed to the owner based on a design conversation from 2026-09-23.

The original source is not archived in the repository; therefore, this answer can be traced to a provenance record, but the original wording cannot be verified here. If the query depends on exact words or full nuance, the conversation history must be opened.

## What this demonstrates

The project file is an entry point to the current state. The decision summarizes a choice; the claim separates attributed content from its source; the source record documents origin and limits. The snapshot preserves a historical version only because it was chosen as a checkpoint. If any of these links is missing, that should be made visible rather than invented.

**¿Qué enfoque metodológico se acordó para Theuth y de dónde procede?**
